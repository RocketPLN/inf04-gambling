# AGENTS.md

INF.04 Portal. Polish study app for the INF.04 technik programista practical exam. It turns CKE exam PDFs (2021-2026, styczen/czerwiec sessions) into browsable HTML and pairs each exam sheet with a live CKE scoring counter (R1-R4).

## Stack

React 19, Vite 8, TanStack Router with file-based routes, plain JSX (no TypeScript in `src`), oxlint for lint. Python with PyMuPDF handles the PDF to HTML conversion. There is no test runner.

Environment I saw: Node v24, npm 11, Python 3.14, pymupdf 1.28.2.

## Commands

All from repo root. The repo has both `package-lock.json` and `pnpm-lock.yaml`, but scripts and docs assume npm, so use npm.

- `npm run dev` starts Vite locally.
- `npm run build` builds to `dist/`.
- `npm run preview` serves the production build.
- `npm run lint` runs `oxlint`.
- `npm run download` runs `scripts/download-pdfs.js`, fetches PDFs and ZIPs from arkusze.pl into `public/pdfs/`, writes placeholder plans into `public/plans/`.
- `npm run convert` runs `python3 scripts/transform_pdfs.py`, the real PDF to HTML conversion with PyMuPDF. Needs `pip install pymupdf`.
- `npm run convert:legacy` runs `python3 scripts/pdf_to_html.py`, older converter, only use it when asked.
- `npm run setup` chains download, convert, and build. It hits the network and takes a while, so prefer `dev` plus `convert` for normal work.

## Layout

- `src/main.jsx` wires `RouterProvider` with the generated route tree. This is the entry point.
- `src/routes/__root.jsx` shared shell (ticker, jackpot bar, header, footer, bonus bar).
- `src/routes/index.jsx` home page, exam grid, filters, search params `q`, `year`, `session`.
- `src/routes/egzamin.$examId.jsx` single exam page, loads exam by `params.examId`, throws `notFound()` for unknown ids.
- `src/routeTree.gen.ts` generated by TanStack Router. Never edit by hand.
- `src/data/exams.js` source of truth for exams, plans, and scoring. 11 entries, `inf04-2021-czerwiec` through `inf04-2026-czerwiec`.
- `src/components/PlanView.jsx` canonical exam detail view, fetches converted HTML, renders tasks, files, and the scoring counter. Exports `FungusWhisper`, used across pages.
- `src/components/ScoringCounter.jsx` CKE checklist with localStorage persistence.
- `src/components/CasinoScam.jsx` jackpot bar, slot machine, fake winners ticker, bonus bars. All satire, all intentional.
- `src/App.jsx` legacy single-file app from before the router migration. `main.jsx` no longer renders it. Do not revive it, do not port changes into it. If it confuses you, leave it alone or ask before deleting.
- `src/App.css`, `src/index.css` global styles, brutalist and casino classes live here.
- `scripts/download-pdfs.js` downloader plus placeholder HTML writer.
- `scripts/transform_pdfs.py` real converter, outputs standalone and fragment HTML plus images.
- `scripts/pdf_to_html.py` legacy converter.
- `public/plans/` generated HTML. Each exam has `<id>.html` (standalone page) and `<id>.fragment.html` (inner content fetched by React). Images go to `public/plans/img/`.
- `public/pdfs/` downloaded source PDFs and attachment ZIPs, named `<id>-arkusz.pdf`, `<id>-zasady.pdf`, `<id>-zalaczniki.zip`.
- `index.html` Polish `lang="pl"`, title and meta for INF.04, Google Fonts (Bricolage Grotesque, DM Sans, JetBrains Mono).
- `.oxlintrc.json` enables `react` and `oxc` plugins. `react/rules-of-hooks` is an error, `react/only-export-components` is a warn with `allowConstantExport`, so exporting `FungusWhisper` next to `PlanView` is fine.

## Routing

Routes are file-based. Adding `src/routes/foo.jsx` with `createFileRoute("/foo")` is enough, the Vite plugin regenerates `routeTree.gen.ts` on `dev` and `build`.

Search params are the filter state. `__root.jsx` validates them (`q` string, `year` string or `"all"`, `session` `"styczeń"`, `"czerwiec"`, or `"all"`). `index.jsx` reads them with `Route.useSearch()` and writes with `navigate({ search })`. Card links forward them to `/egzamin/$examId` so the back button restores filters. Keep these three files in sync when you touch filters. Session strings contain Polish diacritics, match them exactly.

Unknown exam ids render the `notFoundComponent` in `egzamin.$examId.jsx` plus set `document.title` accordingly.

## Data model

Each object in `src/data/exams.js` looks like this:

`id`, `year` (number), `session` (`"styczeń"` or `"czerwiec"`), `title`, `subtitle`, `pdfArkusz`, `pdfZasady`, `zipZalaczniki` (path or `null`), optional `zipRemote`, `tech` (array), `czas` (minutes), `plan` (`opis`, `zadania`, `pliki`, `wymagania`), `scoring` (array of R1-R4 groups, each with `grupa`, `max`, and `kryteria` of `kod`, `opis`, `pkt`).

Every criterion is worth 1 pkt. Group `max` equals its criteria count and exam total is the sum of group maxes. Derive totals with `reduce`, never hardcode them in new UI.

The same exam list is duplicated in `scripts/download-pdfs.js` and `scripts/transform_pdfs.py` (`EXAMS`). There is no shared import, JS and Python cannot share it cleanly here. When you add or rename an exam, update all three files or the pipeline and the UI will drift apart.

## PDF to HTML pipeline

Flow: `download-pdfs.js` fetches sources into `public/pdfs/`, then `transform_pdfs.py` parses each PDF with PyMuPDF dict output, detects headings, lists, and UWAGA blocks, extracts images with `get_images` into `public/plans/img/`, and writes two files per exam.

`PlanView.jsx` fetches `/plans/<id>.fragment.html` first, parses it with `DOMParser`, and injects `.transformed-content`. On failure it falls back to `/plans/<id>.html` and looks for `.content` or `.pdf-pages`. If that fails too, it shows an iframe or an error with a direct link. PDF preview iframes use `exam.pdfArkusz` and `exam.pdfZasady`, which point at arkusze.pl for exams without a local copy.

Rules: never hand-edit files in `public/plans/`, rerun `convert` instead. Do not commit fresh multi-megabyte PDFs unless asked, they bloat the repo. Note that `transform_pdfs.py` only carries full scoring markup for `inf04-2024-czerwiec` in `SCORING`, everything else falls back to `GENERIC`. The React `exams.js` scoring is richer and is what the counter uses, so do not copy criteria out of generated HTML.

## Style is intentionally ugly

The casino look is the point. Marquee tags, Comic Sans inline styles, jackpot counters, fake winner tickers, RTP pills, kurs multipliers, "ODBIERZ BONUS" buttons, testimonial jokes, guest counters, `FungusWhisper` mushroom traces. Do not "fix" these, do not normalize them into clean corporate UI, do not remove jokes in a refactor. Keep Polish copy as is, including diacritics and caps-lock shouting.

`FungusWhisper` renders a subtle mushroom marker, `variant="corner"` for card corners. It appears on every 5th card and in a few footers. Leave it.

## State and conventions

Scoring state persists per exam in `localStorage` under `inf04-checked-v2-<examId>`. Keep the key format, users have saved checklists under it. Grade thresholds in `ScoringCounter.jsx` are 50, 75, 90 percent, with 75 labelled zdany. Task anchor buttons scroll the converted HTML via `handleHighlight` using the map `implementacja`, `konsolowa`, `aplikacja`, `dokumentacja`. Keep anchor names stable, both `PlanView` copies reference them.

Write JSX in the existing style: function components, hooks at top, double quotes in JS, Polish UI strings. Converted exam HTML goes through `dangerouslySetInnerHTML`, so never inject user input or search text into it. Filter text only touches the exam list, never the HTML fragment.

## Verification

There are no unit tests, so verification is lint plus build plus a manual pass.

1. `npm run lint` must be clean.
2. `npm run build` must pass, which also regenerates the route tree.
3. `npm run dev`, open `/`, filter by a tech tag and a session, open an exam, check the fragment loads, toggle a few R-criteria and reload to confirm persistence, check back navigation restores filters.

If you touched `scripts/transform_pdfs.py`, run it on one exam and diff `public/plans/<id>.fragment.html` before regenerating everything.
